# Changelog

## v83 — Тарифы из шахматки RealtyCalendar для ИИ-ассистента (15.10.2026)

### Что появилось
- **Цены за ночь из календаря**: CRM раз в час забирает из шахматки RealtyCalendar цену каждой квартиры на каждый
  день на 180 дней вперёд (таблица `rc_rates`, модуль `backend/rc_rates.py`). Первая выгрузка перебирает несколько
  известных запросов календаря, запоминает тот, что отдал цены, и дальше пользуется только им; если запрос
  перестал работать — подбор повторяется.
- **Интеграции → Подключения → RealtyCalendar**: строка «Тарифы из шахматки: N кв. по <дата> · обновлено …» и кнопка
  «Загрузить тарифы». Если календарь не отдал цены, кнопка показывает таблицу попыток (запрос, код ответа,
  примечание) — её достаточно переслать разработчику.
- **ИИ-ассистент считает стоимость сам**: инструмент `check_availability` теперь возвращает для свободных квартир
  цену за ночь, итог за период в долларах и в сумах, минимальный срок и пометку, если на часть дат цены нет.
  Фильтр по квартире или блоку (A / B). Правила ассистента: цены и свободные даты — только из календаря; если
  тарифа нет — уточнить у менеджера.
- **Курс доллара** (Интеграции → ИИ-ассистент, по умолчанию 11 850 сум): по нему ассистент переводит цены в сумы,
  когда гость просит.
- Маршруты: `GET /api/crm/rc/rates` (состояние), `POST /api/crm/rc/rates/sync` (выгрузить сейчас, админ),
  `GET /api/crm/rc/rates/quote?checkin&checkout` (свободные квартиры с ценами).
- В демо-режиме (без RC_TOKEN) тарифы заполняются тестовыми значениями, чтобы ассистент работал и на стенде.

## v82 — ИИ-ассистент в чатах, этап 1 (15.10.2026)

### Что появилось
- **Интеграции → ИИ-ассистент**: ключ API Anthropic, режим по умолчанию (выключен / черновики / авто), модели
  (основная — Claude Opus 5.5, сортировка и память — Claude Haiku 5.5), лимит расходов в месяц, каналы, пауза после
  ответа человека, правила для ассистента, база знаний (цены, условия, реквизиты, адрес), кнопки «Проверить ключ» и
  «Примеры из истории», расход за день и месяц, журнал последних действий ИИ.
- **В каждом чате**: переключатель «ИИ: как в настройках / выкл / черновик / авто» в шапке и кнопка ✨ «Ответить с ИИ».
  Черновик показывается над полем ввода: «Отправить», «Вставить и править», «Другой вариант», «Убрать».
  Сообщения, отправленные ассистентом, подписаны «✨ ИИ-ассистент».
- **Как работает**: после каждого входящего (с паузой 20 с, чтобы собрать несколько сообщений подряд) дешёвая модель
  решает, нужен ли ответ и нужен ли человек. Если нужен человек — чат помечается, ставится задача «Ответить гостю»,
  уходит уведомление в Telegram (рабочий чат и сотрудники, привязавшие Telegram). Иначе основная модель отвечает,
  видя всю историю чата (включая фото), карточку гостя с «памятью о госте», брони и прошлые заезды, базу знаний и
  похожие ответы команды из истории. Инструменты: свободные квартиры на даты (из календаря), время приезда (в список
  горничным), заявка на бронь (сделка + задача менеджеру «Подтвердить бронь» + уведомление), передача человеку.
- **Безопасность**: авто-режим работает только в указанных каналах; как только в чате ответил человек, ИИ молчит
  заданное число часов; после N ответов без результата передаёт человеку; при исчерпании месячного лимита авто-режим
  превращается в черновики; тексты с незаполненными данными не уходят.
- **Обучение**: пары «вопрос гостя → ответ менеджера» из прошлых переписок собираются кнопкой без обращений к модели и
  подставляются как примеры; черновик, который менеджер поправил перед отправкой, тоже становится примером.

### Что сделать после обновления
1. Установить библиотеку: запустить `install.bat` (или `pip install anthropic`), затем перезапустить сервер.
2. CRM → Интеграции → ИИ-ассистент: вставить ключ API, нажать «Проверить ключ», заполнить базу знаний, нажать
   «Примеры из истории». Режим по умолчанию «Черновики» — безопасный старт; «Авто» включать на отдельных чатах.

## v79 — Booking.com: догрузка пропущенных сообщений (13.10.2026)

### Что изменилось
- **Причина потерь найдена**: когда сессия экстранета истекала (или вкладка была закрыта, или CRM перезапускалась),
  расширение пыталось открыть новые треды, не могло — а сервер всё равно помечал пару «гость + превью» как
  прочитанную. После входа в экстранет те же превью считались уже прочитанными, и сообщения не забирались, пока гость
  не писал снова. Теперь «прочитано» ставится только после успешного открытия; неудачное открытие повторяется до
  3 раз.
- **Догрузка после сбоя**: сервер запоминает, когда связь с экстранетом пропала (истёкшая сессия, страница входа,
  закрытая вкладка, нет связи больше 3 минут, перезапуск CRM). Как только расширение снова на связи, включается режим
  догрузки: расширение листает весь список переписок (а не только видимые сверху), а сервер сравнивает каждый тред с
  тем, что есть в CRM, забыв пометки «прочитано», сделанные во время сбоя. Треды открываются с прокруткой на несколько
  экранов вверх, чтобы забрать не только последнее сообщение. Догрузка заканчивается, когда два полных прохода подряд
  не находят ничего нового (максимум 45 минут).
- **Кнопка «Догрузить пропущенное»** на странице Каналы → Booking.com запускает то же вручную за последние 7 дней;
  рядом виден ход догрузки и результат последней.
- В обычном режиме тред, в котором последнее сообщение CRM старше 6 часов, тоже читается на два экрана вверх.

### Что сделать после обновления
1. Перезапустить сервер.
2. Обновить расширение: chrome://extensions → ⟳ на карточке Nova Booking (нужна версия 1.9).
3. Открыть CRM → Каналы → Booking.com → «Догрузить пропущенное» — заберёт то, что пропало на этой неделе.

  статус WhatsApp в чатах — раз в минуту; поиск по чатам с задержкой 150 мс (P9, P17).
- **Проверка доступа к чатам** не блокирует event loop: зависимость синхронная (threadpool), кука CRM и список
  сотрудников кэшируются на 5–10 с (P14, P16).
- **Правила автосообщений** читают из журнала только свои ключи, а не весь журнал; записи старше 90 дней удаляются (P12).
- **Задачи и сделки** подгружают только нужных клиентов, а не всю таблицу (P11).
- `/crm/` и `/inbox/` получили `Cache-Control: no-cache`: после обновления оболочка не ссылается на старые файлы (P18).

  неполная выдача календаря «отменяла» сделки. Теперь обновляется только окно синхронизации (вчера … +60 дней), брони
  вне окна остаются как история, а раз в сутки подтягивается прошлый год — у постоянных гостей видны прежние заезды.
- **Бронь считается отменённой только после двух пропусков подряд** в выдаче календаря. Снятая бронь архивируется
  в `bookings_cancelled`, сделка уходит в «Отменена», незавершённые автосообщения по ней закрываются, время приезда
  удаляется, владельцам приходит уведомление в Telegram. Если бронь вернулась в календарь — сделка возвращается в воронку.
- **Правило «Новая бронь»** срабатывает по моменту, когда CRM впервые увидела бронь (`first_seen`), а не по времени
  последней синхронизации; старые брони при импорте истории под него не попадают (C5).
- **Воронка броней уважает ручные переносы** (новый столбец `flow_key`): сделку двигает только изменение состояния самой
  брони (оплата, заезд, выезд, отмена), а не каждый прогон. Цвет оплаты в воронке теперь учитывает статус брони (B1):
  «не подтверждена» больше не превращалась в «Ожидает оплаты».
- **Действия этапа** выполняются один раз в день на сделку: при двойной обработке переноса задача или сообщение
  не дублируются (B3).
- **Автосообщения чек-листа**: неудачная отправка повторяется не чаще раза в час и не более 3 раз, затем задача
  остаётся человеку с причиной (B10). Для брони старше суток этапы «сразу после брони» закрываются как пропущенные,
  а не рассылаются задним числом (B9).
- **Задачи**: страница открывается в режиме «Сегодня» (срок до конца дня + без срока), переключатели «Неделя» и «Все»;
  счётчики на главной и в меню считают задачи на сегодня (C6). Срок сравнивается по местному времени, а не по UTC —
  задача на 02:00 не была «просрочена» в 21:00 накануне (B16).
- **Время заезда/выезда и отчёта** нормализуется до `ЧЧ:ММ` при сохранении и при чтении: `9:05` и `14:00:00` больше
  не ломают сортировку, планировщик отчёта и расчёт «успеем ли убрать» (B4).
- **Главная**: сводка по этапам воронки считалась без группировки (B13) — исправлено. Перенос сделки по этапам не
  переименовывает её (B14). Удаление сделки и воронки очищает связанные чаты, заметки и действия этапов (B6).
- **Мелочи**: задачу по уже исчезнувшей брони можно редактировать (U2); сообщение в Booking.com не ставится в очередь,
  пока расширение не на связи (B7); клиент не создаётся из откатившегося чата (B17); привязка чата к брони будит
  long-poll (B11); некорректная дата в `?date=` / `?month=` отвечает 400, а не «пусто» (B15); даты в SQL считаются
  по локальному дню сервера (B19).

### Что сделать после обновления
1. Перезапустить сервер: при старте добавятся столбцы `first_seen`, `flow_key`, `auto_tries` и таблицы
   `bookings_missing`, `bookings_cancelled`. Данные не теряются.
2. Первый прогон воронки запомнит текущие этапы сделок как «свои» — ничего само не переедет.

## v74 — релиз 1 из 5 по аудиту: безопасность (12.10.2026)

Закрыты пункты аудита C1, C2, C3, C7, C8, H3, H4, M1–M10, L1, L3, L6, L8, L10, L12.

### Что изменилось
- **Вебхук Meta (WhatsApp Cloud / Instagram)** отвечает 404, пока не заданы `META_APP_SECRET` и токены; тело ограничено 1 МБ.
  Раньше без секрета он принимал что угодно (C1).
- **Сотрудники в боте**: новый человек после `/start` попадает в список «ожидают», владелец получает уведомление и выдаёт доступ
  командой `/staff_ok <id>`; `/staff_del` отзывает доступ и персональный ключ. Уже активные сотрудники доступ не теряют (C2).
- **Персональные ключи** вместо общего `STAFF_KEY`: ссылка на дашборд у каждого своя, хранится хешем, отзывается (M9).
  Подпись Telegram `initData` старше 48 часов не принимается.
- **Секреты** теперь случайные и независимые от токена бота: файл `data/secrets.json` создаётся при первом запуске
  (`app_secret`, `inbox_secret`). WhatsApp-мост читает тот же файл (C3).
- **Dev-режим** (вход без бота) включается только `DEV_MODE=1`; полунастроенный `.env` больше не открывает данные (H4).
- **Токены не попадают** в ошибки и логи: фильтр маскирует их во всех записях, ошибки Telegram Bot API без URL (C7).
- **Страница Каналы** для роли «менеджер» не содержит токен расширения, адрес вебхука Wazzup, QR и дамп страницы (C8).
- **SSRF-фильтр** `backend/netsafe.py`: медиа из Wazzup, Instagram, WhatsApp Cloud и push-адреса браузеров качаются
  только по https с публичных адресов разрешённых хостов, без редиректов, с лимитом размера (H3, M7).
- **Антибрутфорс** входа считает попытки по реальному IP (`CF-Connecting-IP`) и по email, старые записи чистятся (M1).
- **Первый запуск** на публичном адресе требует код из `data/setup_token.txt` (M2).
- **Медиа**: только картинки, видео, аудио и PDF отдаются inline (с проверкой первых байт), остальное — как вложение,
  `nosniff` + CSP sandbox; подпись ссылки 128 бит (M3, L8).
- **Лимиты тел запросов** на загрузку файла, bridge-hook, вебхуки (M4).
- **Экспорт XLSX** экранирует формулы (M5); **PDF** экранирует данные гостя и компании (M6).
- **Email из CRM**: менеджер пишет только на адрес гостя из карточки или брони; `backfill`/`import` только админу;
  ручная синхронизация не чаще раза в минуту для менеджера (M8).
- **Выход** отзывает куку на всех устройствах; смена пароля требует текущий пароль; минимум 8 символов в форме (M10).
- `/docs`, `/redoc`, `/openapi.json` закрыты (L1); `Secure` у куки по реальной схеме запроса (L6);
  расширение хранит настройки в `storage.local` и принимает только https-адрес CRM (L10).

### Что сделать после обновления
1. Перезапустить сервер и WhatsApp-мост (`restart_all.bat`): мост подхватит новый секрет из `data/secrets.json`.
2. Войти в CRM заново (все старые куки недействительны).
3. Расширение Booking.com: открыть CRM → Каналы (под админом), скопировать новый ключ и вставить в настройки расширения.
4. Wazzup: нажать «Подключить вебхук заново» на странице Каналы (адрес вебхука изменился). Сервер делает это и сам при старте.
5. Сотрудникам, которые открывали чаты по ссылке из бота, снова написать боту `/chats`.
