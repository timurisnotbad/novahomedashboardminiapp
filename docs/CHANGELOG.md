# Changelog

## v93 — Правки сообщений из мессенджеров видны в CRM; цифры на главной не вылезают из плиток (20.10.2026)

- **Изменённые сообщения.** Если гость (или кто-то из команды с телефона) отредактировал сообщение в Telegram или
  WhatsApp, CRM теперь показывает новый текст с пометкой «изменено» (время правки — в подсказке), превью в списке
  чатов обновляется. Telegram-аккаунт: событие редактирования; WhatsApp по QR: правка приходит из моста
  (после обновления перезапустите `restart_all.bat`, чтобы перезапустился мост); Wazzup: повторная доставка того
  же сообщения с другим текстом считается правкой.
- **Главная:** плитки больше не выпускают длинные числа за границу: размер цифр подстраивается под ширину,
  перенос разрешён, на средних экранах пять плиток ложатся в три колонки.

## v92 — Каждый входящий лид регистрируется: @username сразу, телефон — как только появится (17.10.2026)

- **Карточка клиента создаётся при первом же сообщении** из любого канала (WhatsApp, Telegram, Instagram через
  Wazzup или напрямую). Для Telegram и Instagram в карточку сразу пишется @username (поля «Telegram» /
  «Instagram»), он же виден в шапке чата ссылкой на профиль.
- **Телефон подхватывается, когда становится известен:** гость добавил нас в контакты или открыл номер (Telegram
  отдаёт его при следующем сообщении), прислал свою визитку-контакт, или написал номер в тексте («мой номер
  +998 90 …»). Номер попадает и в чат (для сопоставления с бронями), и в карточку.
- **Без дублей.** Если у чата была карточка без телефона, а номер совпал с уже известным гостем (например, из
  брони на Booking), карточки объединяются: сделки, задачи, заметки и @username переезжают на одну.
- Чужая визитка (водитель, друг) в чате не становится номером гостя: она сохраняется как второй телефон.
  Исходящие сообщения с нашим номером не учитываются.
- **Старые чаты тоже.** Через полторы минуты после первого запуска новой версии CRM один раз проходит по всем
  существующим чатам: номера и @username из самих чатов, визитки и номера из текста прошлых сообщений — в
  карточки; у Telegram заново запрашиваются профили всех собеседников. Повторить можно кнопкой
  «Собрать контакты из переписок» (Интеграции → Подключения).

## v91 — Кнопка ✨ больше не обрывается «Нет связи с сервером» (15.10.2026)

- «Ответить с ИИ» ставит задачу и отвечает сразу; модель с инструментами и фото думает 10–40 секунд, и такое

## v90 — Скорость: кэш статики, параллельные запросы, неблокирующий Telegram-скрипт (15.10.2026)

Замеры: сервер отвечает на каждый запрос за 5–80 мс, поэтому медленно было не из-за базы, а из-за
количества последовательных обращений через туннель и повторной загрузки файлов интерфейса.

- **Статика кэшируется.** Скрипты и стили с `?v=<версия>` отдаются с `Cache-Control: immutable` на год (раньше
  каждый файл проверялся на сервере при каждом открытии — это по одному обращению через туннель на файл);
  иконки и шрифты — на день. HTML-оболочка по-прежнему проверяется всегда, поэтому обновления подхватываются
  без Ctrl+F5.
- **Запросы страниц идут параллельно.** «Интеграции»: 8 последовательных запросов → одна волна (при задержке
  туннеля 120 мс: 0,8 с → 0,2 с). «Клиенты», «Сделки», вкладка ИИ, таблица квартир — то же. Страница чатов
  запрашивает профиль, список чатов и шаблоны одновременно.
- **Скрипт Telegram Mini App** больше не грузится внутри CRM (там он не нужен) и не блокирует отрисовку чатов,
  когда telegram.org отвечает медленно.

## v89 — Задачи без автоматического мусора; WhatsApp через Wazzup без «Нужен QR» (15.10.2026)

### Задачи
- **В списке задач, на главной и в бейдже — только задачи людей и ИИ-ассистента.** Автоматические шаги
  («Заезд», «Выезд», шаги сценария заезда) больше не считаются и не показываются: сценарий по-прежнему
  отправляет сообщения, его шаги видны в карточке брони и на странице «Автосообщения».
- Автозадачи «Заезд»/«Выезд» выключены по умолчанию (Интеграции → «Задачи из броней»), открытые старые
  удаляются при первом запуске новой версии один раз. Ручное добавление задач как было: «Задачи» → «Новая задача».

### Каналы
- Если настроен Wazzup, плашка над чатами показывает «WhatsApp · Wazzup» зелёным вместо красного «Нужен QR»,
  а карточка «WhatsApp — привязка по QR» на странице «Каналы» свёрнута как запасной способ.

## v88 — Вкладка ИИ-ассистента переделана; видно, почему он молчит (15.10.2026)

### Интерфейс
- **Вкладка «ИИ-ассистент» собрана заново.** Сверху чек-лист «что настроено»: ключ, тарифы из шахматки, база
  знаний, описания и фото квартир, изученные переписки, голосовые — с подсказкой, где это включить. Ниже
  разделы, каждый про одно: «Подключение» (ключи), «Режим работы» (где и как отвечает, дожим, пауза, лимит,
  курс), «Что он знает» (база знаний; факты из переписок показываются только когда они есть, с кнопкой
  «перенести в базу знаний»), «Обучение» (изучить переписки, памятка о стиле, уроки). Модели, правила и
  методика продаж спрятаны в «Для продвинутых», журнал действий — в «Журнал». В каждом разделе своя кнопка
  «Сохранить», открытые разделы остаются открытыми после сохранения.
- **В чате видно, что сделал ИИ.** Если ассистент промолчал, передал человеку или упал с ошибкой, под шапкой
  чата появляется строка «✨ ИИ 17:42 · промолчал: гость поблагодарил» с кнопкой «ответить с ИИ». Раньше
  молчание выглядело как «через раз работает».

### Поведение
- **Глубина обдумывания** ответа: новая настройка (быстро / обычно / максимально), по умолчанию «обычно» вместо
  прежнего минимума — ответы заметно лучше держат контекст переписки.
- Сортировщик смотрит 12 последних сообщений вместо 8 и молчит только на явное «спасибо / ок / понял» без
  вопроса; любое уточнение, вопрос или новые данные (даты, число гостей) — повод ответить.
- Обработанное сообщение (в том числе пропущенное) не триажится повторно.

## v87 — Фото квартир от ассистента, устойчивая страница «Каналы» (15.10.2026)

### Что появилось
- **Фото квартир.** В таблице квартир (Интеграции → Сценарий заезда) колонка «Фото»: сколько угодно снимков
  (до 30 уходит за раз) на квартиру или на блок (A / B — запасной вариант для квартир без своих фото). JPG, PNG,

- **Ассистент отправляет фото.** Инструмент `send_photos`: предложив квартиру или по просьбе гостя, ассистент

  они прикрепляются к черновику (панель показывает «📷 вместе с ответом уйдут фото: B-005»), и «Отправить»
  отправляет текст и фото одним действием. Если у квартиры нет фото, ассистент пишет, что их пришлёт менеджер.
  В списке свободных квартир ассистент видит, сколько фото есть у каждой.

### Исправлено
- **«Ошибка 500» на странице Каналы.** Теперь сбой одного канала (Telegram, Wazzup, Meta, расширение Booking)
  не роняет всю страницу: его карточка показывает текст ошибки, остальное работает; причина пишется в
  `logs/server.log`.

## v86 — ИИ-ассистент: контекст без потерь, база опыта, разбор переписок (15.10.2026)

### Исправлено
- **Терял сообщения, пришедшие пока он думал.** Гость писал «хочу забронировать», через секунды «2 человека, 21-24 декабря» —
  ассистент отвечал только на первое и переспрашивал даты. Теперь он помнит, на какое сообщение гостя ответил
  (`ai_last_in_id`); если во время генерации пришли новые сообщения, готовый ответ отбрасывается (в журнале
  «stale») и формируется заново с полным контекстом. Если после гостя ответил человек, ассистент молчит.
- В истории для модели её собственные сообщения помечены «[ты]», сообщения людей — «[менеджер Имя]» /
  «[менеджер с телефона]»: раньше она принимала свои старые ответы за чужие.

### Что появилось
- **База опыта (уроки).** Когда менеджер исправил черновик ассистента, ответил после него иначе или поставил 👎,
  дешёвая модель формулирует один общий урок («„брат“ — это обращение, а не имя», «не предлагай скидку сам»).
  Дубликаты и ситуативные различия пропускаются. Уроки видны в Интеграции → ИИ-ассистент → «Опыт ассистента»,
  их можно добавлять вручную, выключать и удалять; активные входят в каждый запрос.
- **«Изучить переписки» стало глубже:** памятка о стиле теперь с разделом «как отвечает каждый» по авторам, плюс
  отдельное поле «Факты из переписок» — что команда реально отвечала про предоплату, регистрацию, оплату,
  парковку. Факты входят в запрос с оговоркой, что база знаний главнее; проверьте их и перенесите важное.
- **Словарь сокращений и обращений** в правилах: «брат/братан/ака» — обращение, «скок», «чел», «сут», «кв»,
  «нал», «ок/xo'p», «4 вариант» и т.д. Правило читать несколько сообщений подряд как один запрос.
  Запрет писать «Фото» и обещать ссылки, которых нет; не перечислять все квартиры списком.

## v85 — Методика продаж для ИИ-ассистента и дожим молчащих гостей (15.10.2026)

### Что появилось
- **Методика продаж** (Интеграции → ИИ-ассистент, поле с кнопкой «вернуть по умолчанию»): как опытный
  менеджер по бронированию ведёт гостя в переписке — ответ по сути первой фразой, один вопрос за сообщение,
  выявление потребности (даты → состав → цель → что важно), 2–3 варианта с «почему именно вам», ценность до
  цены, цена за ночь и итог без доплат, готовые ответы на возражения (дорого, подумаю, нашли дешевле, скидка,
  безопасно ли, предоплата, нет отзывов, далеко, ЗАГС, регистрация), честная срочность, закрывающие вопросы,
  резюме брони, одно напоминание при молчании, правила тона (вы/siz, aka/opa, эмодзи 0–1, имя ≤3 раз,
  запрещённые обороты, извинение один раз), когда звать человека. Собрана из практик Airbnb, Booking, Vrbo,
  Kennedy Training Network, Revinate, Говорухина, RetailCRM, исследований о восприятии ботов и источников по
  узбекскому этикету — обоснование и ссылки в `docs/AI-SALES-PLAYBOOK.md`.
- **Дожим**: если гость замолчал после предложения ассистента, через N часов (настройка «Дожим», по умолчанию 3;
  0 — выключить) он отправляет одно короткое напоминание с вопросом «да/нет». Только в режиме «отвечает сам»,
  только днём (09:00–21:00), один раз на молчание; если напоминание неуместно (гость отказался, попрощался),
  модель отвечает служебным словом и ничего не отправляется. Видно в журнале ИИ как «followup».
- **Чек-лист базы знаний** в подсказке поля: предоплата, оплата, регистрация E-mehmon, ЗАГС, парковка, дети и
  животные, ранний заезд, скидки, документы для командированных, отзывы и адрес. Без этих политик ассистент
  честно передаёт вопрос менеджеру.

## v84 — ИИ-ассистент: тест по чатам, человеческий стиль, узбекский, голосовые (15.10.2026)

### Что изменилось
- **Тумблер вместо «везде сразу»**: режим по умолчанию теперь «Выключен везде, кроме чатов, где включён вручную».
  ИИ включается в шапке конкретного чата («ИИ: черновик (тест)» или «ИИ: отвечает сам»), в остальных молчит.
  Кнопка ✨ готовит черновик в любом режиме.
- **Новые правила по умолчанию** (старые сохранённые правила v82/v83 автоматически заменяются): сценарий «даты и
  число гостей → шахматка → 2–3 варианта с ценой → имя и телефон → заявка»; ответ на языке гостя (русский, узбекский
  латиницей или кириллицей, английский) со словариком разговорного узбекского (nechpul, bosh, bormi…); даты словами и
  без года; без «минуту, проверяю» и канцелярита; **никогда не называться именем сотрудника** — на вопрос «ты бот?»
  честно отвечает, что он ассистент Nova Home; название чата или контакта — не запрос гостя.
- **«Изучить переписки»** (Интеграции → ИИ-ассистент): собирает примеры «вопрос → ответ команды» и составляет памятку
  о стиле команды (тон, обращения, типичные фразы на трёх языках, как называют цены). Памятка редактируется и входит
  в каждый запрос к модели.
- **Голосовые → текст**: при ключе OpenAI (поле в той же вкладке, ≈0,3 ¢ за минуту) входящие голосовые
  расшифровываются автоматически; текст виден команде под сообщением (🎙) и читается ассистентом. Кнопка «🎙 Текст»
  на старых голосовых. Сортировщик определяет язык сообщения, ответ идёт на нём.
- **Описание квартир для гостей**: новая колонка в таблице квартир (Сценарий заезда): комнаты, гостей, этаж, вид.
  Ассистент видит её и в списке свободных квартир, и в базовых данных — может предлагать, а не только перечислять.
- **Подпись ИИ в чате**: ответы ассистента подписаны «✨ ИИ-ассистент» и в списке чатов (✨ перед текстом). Эхо
  отправленного сообщения из Telegram больше не превращается в сообщение «Телефон» (сравнение без пробелов, окно 10 мин).
- Расход на расшифровку и памятку о стиле виден в журнале ИИ.

## v83 — Тарифы из шахматки RealtyCalendar для ИИ-ассистента (15.10.2026)

### Что появилось
- **Цены за ночь из календаря**: CRM раз в час забирает из шахматки RealtyCalendar цену каждой квартиры на каждый
  день на 180 дней вперёд (таблица `rc_rates`, модуль `backend/rc_rates.py`). Первая выгрузка перебирает несколько
  известных запросов календаря, запоминает тот, что отдал цены, и дальше пользуется только им; если запрос
  перестал работать — подбор повторяется.
- **Интеграции → Подключения → RealtyCalendar**: строка «Тарифы из шахматки: N кв. по <дата> · обновлено …» и кнопка
  «Загрузить тарифы». Если календарь не отдал цены, кнопка показывает таблицу попыток (запрос, код ответа,
  примечание) — её достаточно переслать разработчику.
- **ИИ-ассистент считает стоимость сам**: инструмент `check_availability` теперь возвращает для свободных квартир
  цену за ночь, итог за период в долларах и в сумах, минимальный срок и пометку, если на часть дат цены нет.
  Фильтр по квартире или блоку (A / B). Правила ассистента: цены и свободные даты — только из календаря; если
  тарифа нет — уточнить у менеджера.
- **Курс доллара** (Интеграции → ИИ-ассистент, по умолчанию 11 850 сум): по нему ассистент переводит цены в сумы,
  когда гость просит.
- Маршруты: `GET /api/crm/rc/rates` (состояние), `POST /api/crm/rc/rates/sync` (выгрузить сейчас, админ),
  `GET /api/crm/rc/rates/quote?checkin&checkout` (свободные квартиры с ценами).
- В демо-режиме (без RC_TOKEN) тарифы заполняются тестовыми значениями, чтобы ассистент работал и на стенде.

## v82 — ИИ-ассистент в чатах, этап 1 (15.10.2026)

### Что появилось
- **Интеграции → ИИ-ассистент**: ключ API Anthropic, режим по умолчанию (выключен / черновики / авто), модели
  (основная — Claude Opus 5.5, сортировка и память — Claude Haiku 5.5), лимит расходов в месяц, каналы, пауза после
  ответа человека, правила для ассистента, база знаний (цены, условия, реквизиты, адрес), кнопки «Проверить ключ» и
  «Примеры из истории», расход за день и месяц, журнал последних действий ИИ.
- **В каждом чате**: переключатель «ИИ: как в настройках / выкл / черновик / авто» в шапке и кнопка ✨ «Ответить с ИИ».
  Черновик показывается над полем ввода: «Отправить», «Вставить и править», «Другой вариант», «Убрать».
  Сообщения, отправленные ассистентом, подписаны «✨ ИИ-ассистент».
- **Как работает**: после каждого входящего (с паузой 20 с, чтобы собрать несколько сообщений подряд) дешёвая модель
  решает, нужен ли ответ и нужен ли человек. Если нужен человек — чат помечается, ставится задача «Ответить гостю»,
  уходит уведомление в Telegram (рабочий чат и сотрудники, привязавшие Telegram). Иначе основная модель отвечает,
  видя всю историю чата (включая фото), карточку гостя с «памятью о госте», брони и прошлые заезды, базу знаний и

## v79 — Booking.com: догрузка пропущенных сообщений (13.10.2026)

### Что изменилось
- **Причина потерь найдена**: когда сессия экстранета истекала (или вкладка была закрыта, или CRM перезапускалась),
  расширение пыталось открыть новые треды, не могло — а сервер всё равно помечал пару «гость + превью» как
  прочитанную. После входа в экстранет те же превью считались уже прочитанными, и сообщения не забирались, пока гость

- **Догрузка после сбоя**: сервер запоминает, когда связь с экстранетом пропала (истёкшая сессия, страница входа,
  закрытая вкладка, нет связи больше 3 минут, перезапуск CRM). Как только расширение снова на связи, включается режим
  догрузки: расширение листает весь список переписок (а не только видимые сверху), а сервер сравнивает каждый тред с
  тем, что есть в CRM, забыв пометки «прочитано», сделанные во время сбоя. Треды открываются с прокруткой на несколько
  экранов вверх, чтобы забрать не только последнее сообщение. Догрузка заканчивается, когда два полных прохода подряд
  не находят ничего нового (максимум 45 минут).
- **Кнопка «Догрузить пропущенное»** на странице Каналы → Booking.com запускает то же вручную за последние 7 дней;
  рядом виден ход догрузки и результат последней.
- В обычном режиме тред, в котором последнее сообщение CRM старше 6 часов, тоже читается на два экрана вверх.

### Что сделать после обновления

2. Обновить расширение: chrome://extensions → ⟳ на карточке Nova Booking (нужна версия 1.9).

## v74 — релиз 1 из 5 по аудиту: безопасность (12.10.2026)

Закрыты пункты аудита C1, C2, C3, C7, C8, H3, H4, M1–M10, L1, L3, L6, L8, L10, L12.

### Что изменилось
- **Вебхук Meta (WhatsApp Cloud / Instagram)** отвечает 404, пока не заданы `META_APP_SECRET` и токены; тело ограничено 1 МБ.
  Раньше без секрета он принимал что угодно (C1).
- **Сотрудники в боте**: новый человек после `/start` попадает в список «ожидают», владелец получает уведомление и выдаёт доступ
  командой `/staff_ok <id>`; `/staff_del` отзывает доступ и персональный ключ. Уже активные сотрудники доступ не теряют (C2).
- **Персональные ключи** вместо общего `STAFF_KEY`: ссылка на дашборд у каждого своя, хранится хешем, отзывается (M9).
  Подпись Telegram `initData` старше 48 часов не принимается.
- **Секреты** теперь случайные и независимые от токена бота: файл `data/secrets.json` создаётся при первом запуске
  (`app_secret`, `inbox_secret`). WhatsApp-мост читает тот же файл (C3).
- **Dev-режим** (вход без бота) включается только `DEV_MODE=1`; полунастроенный `.env` больше не открывает данные (H4).
- **Токены не попадают** в ошибки и логи: фильтр маскирует их во всех записях, ошибки Telegram Bot API без URL (C7).
- **Страница Каналы** для роли «менеджер» не содержит токен расширения, адрес вебхука Wazzup, QR и дамп страницы (C8).
- **SSRF-фильтр** `backend/netsafe.py`: медиа из Wazzup, Instagram, WhatsApp Cloud и push-адреса браузеров качаются
  только по https с публичных адресов разрешённых хостов, без редиректов, с лимитом размера (H3, M7).
- **Антибрутфорс** входа считает попытки по реальному IP (`CF-Connecting-IP`) и по email, старые записи чистятся (M1).
- **Первый запуск** на публичном адресе требует код из `data/setup_token.txt` (M2).
- **Медиа**: только картинки, видео, аудио и PDF отдаются inline (с проверкой первых байт), остальное — как вложение,
  `nosniff` + CSP sandbox; подпись ссылки 128 бит (M3, L8).
- **Лимиты тел запросов** на загрузку файла, bridge-hook, вебхуки (M4).
- **Экспорт XLSX** экранирует формулы (M5); **PDF** экранирует данные гостя и компании (M6).
- **Email из CRM**: менеджер пишет только на адрес гостя из карточки или брони; `backfill`/`import` только админу;
  ручная синхронизация не чаще раза в минуту для менеджера (M8).
- **Выход** отзывает куку на всех устройствах; смена пароля требует текущий пароль; минимум 8 символов в форме (M10).
- `/docs`, `/redoc`, `/openapi.json` закрыты (L1); `Secure` у куки по реальной схеме запроса (L6);
  расширение хранит настройки в `storage.local` и принимает только https-адрес CRM (L10).

### Что сделать после обновления
1. Перезапустить сервер и WhatsApp-мост (`restart_all.bat`): мост подхватит новый секрет из `data/secrets.json`.
2. Войти в CRM заново (все старые куки недействительны).
3. Расширение Booking.com: открыть CRM → Каналы (под админом), скопировать новый ключ и вставить в настройки расширения.

5. Сотрудникам, которые открывали чаты по ссылке из бота, снова написать боту `/chats`.
